# sb-easy 产品理念与配置模型

更新于 2026-11-13。服务端是受管设备配置的唯一权威来源：保存一套共享基础配置，以及每台设备在此基础上的个性化 patch。客户端负责编辑、同步和执行，保留运行缓存与离线待提交记录。

## 配置如何组成

```text
服务端共享基础配置（Default）
            ↓ 根据设备能力和授权节点生成
        设备基础配置
            + 服务端保存的设备 patch 与设备运行设置
            ↓ 校验与平台适配
        客户端实际运行配置
```

- 新设备默认使用 Default，设备 patch 为空。
- 修改 Default 后，所有未覆盖相应字段的设备都在下次同步时采用新值。
- 一台设备只改一个字段，不会冻结其余配置；其余字段仍继承默认值。
- 设备 patch 可以新增、修改、删除配置字段。清空 patch 和设备运行设置，就恢复默认继承。
- 管理面板与客户端修改的是服务端保存的同一份设备配置。客户端离线时先记录待提交修改，恢复连接后同步。

“共用基础配置”表示共用策略来源。不同平台的 TUN 参数、设备身份和授权节点仍需适配，不能把某台设备的凭据复制给所有设备。

## 时间戳与双向同步

基础配置和设备 patch 各有版本。版本由服务器按毫秒时间戳生成；即使同一毫秒内连续修改、服务器时钟回拨，也保证新版本递增。客户端自己的时钟只适合显示编辑时间，不决定覆盖顺序。

提交修改时同时带上已读的基础版本和设备版本。服务器发现版本已变，就返回冲突并保留原配置。客户端保留待提交修改，展示服务器新版本，由用户选择重新提交或采用服务器版本。上传响应丢失时，客户端通过下一次读取确认服务器是否已经保存相同内容。

客户端定时同步，无本地修改时只读取服务器更新；有本地修改时提交设备差异。同步缓存和待提交记录跨进程重启保留。服务器不可达时，继续使用上次可用配置。

“已保存到服务器”和“已在设备运行”是两个状态。客户端验证或加载失败时保留上一份可用配置，并报告错误。

## 使用入口

| 入口 | 职责 |
| --- | --- |
| 配置画像 → Default | 编辑所有设备共用的基础配置，保存时检查版本 |
| 设备详情 → 配置 | 查看适配后的基础配置、修改设备 patch、恢复默认 |
| Agent → 运行配置 | 编辑设备 patch、查看待同步/冲突状态、处理冲突 |
| 客户端设备设置 | 编辑本设备个性化策略，定时同步到服务器 |
| 节点与订阅 | 管理基础配置引用的代理资源 |
| 监控与日志 | 查看实际运行状态，区分配置保存成功与应用成功 |

## 兼容与迁移

现有非 Default Profile 和本地设置在首次接入新同步协议时迁移为设备差异，避免丢失已经配置的规则。旧 Profile 继续保留用于兼容；迁移后的设备使用 Default 加自己的 patch，后续修改旧 Profile 不再改变该设备。

未注册服务器的独立模式继续作为兼容入口；注册后的配置按此模型同步。已有加密偏好档案属于备份/导入功能，不承担自动配置同步。

Patch 的字段删除、数组继承边界、接口及迁移细节见 [配置同步协议](config-sync.md)。
