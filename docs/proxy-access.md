# 单端口代理入口

中心管理页 → 配置 → **代理入口**。启用后选择监听地址、一个共享端口，并添加两种入口：

- **跟随规则组**：例如 `google`、`claude`，绑定配置中的 selector/urltest。规则组切换节点后，入口随之变化。
- **固定节点**：用户名自动生成为 `node_完整节点ID`，绑定数据库身份。节点显示名称变化不影响地址，也不会按同名节点重新匹配。

节点列表的 **固定代理地址** 按钮可为当前选中设备所用的配置预填入口；点击保存才会生效。配置是共享的，使用同一配置的设备会一起获得入口，实际可用节点仍取决于设备的节点分配。重复生成同一个节点会打开现有入口，不会重置密钥。

默认监听 `127.0.0.1:1081`，不改变既有入口。需要其他设备访问时，选择合适的监听地址，并在“连接地址中的主机”填写实际运行 agent 的地址。中心服务只管理配置，不自动承担代理流量转发。

保存后等待设备同步，在设备页确认应用成功。然后复制代理地址：

```text
http://google:密钥@agent地址:1081
http://node_节点ID:密钥@agent地址:1081
socks5h://node_节点ID:密钥@agent地址:1081
```

用户名之间可并发使用不同出口，不会切换全局默认节点。HTTP 入口支持 HTTPS CONNECT，不解密目标 TLS。调用方需支持代理认证；某些系统代理设置不支持在地址中填写用户名和密码。

## 行为与兼容性

- `sb-easy-access` 是保留的 mixed 入站标签；用户名/密钥写入原生 `users`，出口写入 `auth_user` 路由，无额外代理服务。
- 每个用户名必须有一个无附加条件的出口规则。规则优先于普通域名分流及 Linux agent 的本地覆盖；QuickJS 不能移除这些入口规则。
- 无认证、错误密钥或未知用户由内核拒绝；认证入口另有兜底拒绝规则。删除最后一个用户必须同时关闭入口，不会退化成无认证代理。
- 固定节点删除、停用或不在设备可用节点中时，下一次同步会将该用户的路由变为拒绝；其他入口继续工作。节点网络不可达时直接失败，不切换备用节点。固定节点不等于运营商保证出口 IP 永远不变。
- `node_` 是固定入口的保留前缀，密码仅用于认证，不参与选择出口。内部 `sb-easy-node-节点ID` 出口独立生成，Linux agent 的本地节点替换不能改变此绑定。
- 规则组不存在时配置渲染报错，需要修正组名。旧版按显示名称绑定的入口会标注“旧版名称绑定”，可主动迁移，不按名称自动猜测数据库节点。
- 管理模式的可用节点取决于设备获分配的节点。完整模式可直接选择模板中的节点和规则组。
- 密钥作为代理配置的一部分保存在中心及设备上；仅向需要使用的人提供。跨不可信网络使用明文 HTTP/SOCKS 入口时，应通过受信任的隧道访问。
- 新的优先级保护需要更新中心服务及 Linux agent。旧版本可识别原生配置，但本地规则可能覆盖入口规则。本次不修改 Windows/Android 客户端界面。

## 验证

```sh
cd frontend && node tests/proxy-access.test.mjs && npm run build
ctest --test-dir build/c -R 'proxy_access|config_renderer|agent_core|http_hosts' --output-on-failure
python3 c/tests/proxy_access_e2e.py /path/to/sing-box
```

真实内核测试只使用临时文件和本机随机端口，验证多个用户名的 HTTP、HTTPS CONNECT、SOCKS 请求并发使用各自出口，以及错误认证被拒绝，不接触生产代理。
